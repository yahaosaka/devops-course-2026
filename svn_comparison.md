# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто файл с хешем коммита (указатель длиной 41 байт), поэтому создаётся мгновенно и локально, без сети. В SVN ветка — это копия каталога в репозитории на сервере (svn copy trunk branches/...): операция идёт через сервер, а слияние веток исторически требовало ручного отслеживания уже влитых ревизий.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история хранится только на сервере, а у разработчика лишь рабочая копия последней ревизии. Коммит — это отправка изменений на сервер, поэтому без связи с ним он невозможен. В Git коммит создаётся в локальном репозитории, а на сервер отправляется позже через git push.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Большие бинарные файлы (геймдев, CAD, дизайн): SVN позволяет выкачать только нужный каталог и блокировать файл (svn lock), чтобы двое не правили один бинарник.
- Строгий централизованный контроль доступа с правами на отдельные каталоги — например, в госсекторе и банках.
- Legacy-проекты, где вся инфраструктура и процессы уже построены вокруг SVN и миграция не окупается.
